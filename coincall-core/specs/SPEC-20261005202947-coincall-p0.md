## 2. 本轮增量裁决（相对 00~09 的 delta，均来自发起人指令）

- **D1 仓库布局**：`coincall-core`（管理面，端口 8020，兼项目制品链宿主）/ `coincall-gateway`（数据面，端口 8030）/ `coincall-bot-chain-api`（已迁移改名，沿用 8010）/ `coincall-contracts`（合约仓）。跨服务数据：core 与 gateway **各自独立 DuckDB 文件**（DuckDB 单写者教训 C-14），gateway 经内部 HTTP 向 core 取 manifest/apikey 校验。
- **D2 keeper 攒批**：`COINCALL_KEEPER_BATCH_SIZE` 默认 **3**，`COINCALL_KEEPER_FLUSH_INTERVAL` 默认 30 秒，链上单笔 chargeWithSigBatch 硬上限 50（04/07/09 已同步修订）。
- **D3 制品路径**：无远端，阶段 6 评审以**本地自查**替代（artifact-chain-guide 新仓接入清单第 5 条）；四个新/迁仓库各自 `AGENTS.md` 声明全量测试入口与绑定校验入口。
- **D4 黄金向量交叉验证**：W2（合约侧）与 W3（网关侧）**各自独立生成** EIP-712 签名黄金向量，汇合阶段比对一致才算冻结生效——两边独立实现能对上，才是向量真正的证明力。
