# AIsa Console 设计语言分析（供 CoinCall 控制台重设计参考）

> 调研方式：2026-10-07 经发起人登录态实地访问 console.aisa.one，覆盖 6 屏：Dashboard（明/暗两态）、API Keys、Playground、Usage & Logs、Billing。
> 纪律：只提取设计原则，不复制布局/文案/内容。

## 1. 页面整体氛围

**观察**：默认浅色主题，克制的开发者工具气质——信息密度中等偏高但不显拥挤；暗色模式为等价一等公民（顶栏一键切换，两态都是完整设计过的色彩体系）。整体感觉是"专业的计量计费台"：数字是主角，装饰几乎为零。品牌存在感收在侧栏 logo 与一处主色强调上。

**可迁移原则**：开发者控制台应呈现"仪表台"而非"营销页"氛围——让数字和状态成为视觉主角；若做暗色则两态同权重设计，不做简单反色。

## 2. 模块节奏

**观察**：清晰的四级节奏——页面级（H1+一句描述+右上动作按钮）→ 指标排（3~4 张等宽统计卡一行）→ 内容区（2 栏网格：图表卡/表格卡）→ 卡内分组。侧栏导航用**功能分组**（Overview / Build / Monitor / Billing & Rewards）+ 两行菜单项（粗体名 + 灰色一句副标注）建立全局节奏。每页只讲一件事，页与页之间结构高度一致。

**可迁移原则**：页面模板化——"标题+副语+主动作 / 指标排 / 内容网格"三段式成为每页的固定骨架；导航按用户任务分组并给每个入口配一句灰字说明（这对双模式产品尤其有价值）。

## 3. 留白方式

**观察**：外侧留白小（内容区贴边距约 24-32px），靠**卡片内边距**（约 20-24px）造呼吸感；卡片间距 16-24px，卡内元素间距 8-12px——间距比例大约 2:1 递进。没有大片装饰性留白，密度服务于"一屏看全账户健康"。

**可迁移原则**：工具型产品留白靠"容器内边距+网格 gap"而不是页边大留白；间距用 8 的倍数体系（8/16/24/32）形成稳定比例。

## 4. 字体层级

**观察**：约 4-5 级——H1（~24-28px/600）、H2 卡片标题（~16-18px/600）、正文（14px/400）、辅助说明（12-13px/灰）。**数字特殊对待**：统计值用 28-32px 的偏大字号+600 字重，金额/用量带 tabular-nums 等宽数字。字号跨度克制，靠字重和颜色拉层级而非无限放大。

**可迁移原则**：14px 正文 + 12px 辅助是工具台基线；把"关键数字"升格为独立层级（大号+等宽+字重）；层级靠灰度阶梯（黑/深灰/中灰/浅灰）表达。

## 5. 卡片样式

**观察**：白底卡 + 1px 极浅描边 + 8-10px 圆角 + **几乎无阴影**（或仅 hover 时极浅投影）；卡片不用重描边或渐变填充强调，层级靠背景与描边的细微差。表格装在"通栏卡"里（卡内含标题行+表格体+空态插画位）。促销/提示条（trial 横幅）是唯一带色彩底色的块，用浅色底+同色系文字，不用大红色。

**可迁移原则**：卡片=白面+细描边+小圆角+无阴影的"纸片"，色彩只留给状态与主按钮；提示条用浅色底同色系字，禁止大面积高饱和告警色。

## 6. 图片比例

**观察**：几乎无摄影图。图形资产仅三类：图表（SVG 面积图，自适应容器）、空态插画（约 3:2 的小幅线描插画）、头像/图标（1:1 圆形或方形线标）。没有 banner 图和营销大图。

**可迁移原则**：工具台不使用装饰图片；图形=数据图表+1:1 图标+小幅空态插画；图表配色单色系+低饱和多色辅助。

## 7. 动效和交互方式

**观察**：动效极度克制——页面切换即时、无入场动画；交互反馈靠状态变化（按钮 loading、表格行 hover 浅灰底、下拉展开）；主题切换瞬时。图表有轻量 hover 十字线。没有视差/滚动动效/大位移转场。

**可迁移原则**：动效预算全部花在"状态可感知"上（loading/hover/展开），零装饰性动画；唯一可加的是数字变化的轻量过渡（计数动画）以强化"计量台"感。

## 8. 颜色和材质感

**观察**：主色为一个饱和度中等的品牌色（用于主按钮/链接/选中态/图表主线），中性色体系完整（背景分层：页面底/卡面/输入框底三层灰阶）；状态色低饱和（成功绿/警示黄/危险红均偏柔和）；暗色模式不是反色而是独立灰阶（卡面比背景亮一档，描边用亮灰）。无玻璃拟态、无渐变横幅、无纹理——材质感=纯色面+细边框。

**可迁移原则**：一个主色+三层中性面+三档低饱和状态色构成全部；暗色用"亮一档的卡面"造层次而非描边加粗；拒绝玻璃拟态/渐变/阴影堆叠。

## 迁移到 CoinCall 的建议

CoinCall 定位差异：双模式（Provider 团队经营 / Consumer 付费调用）+ 链上数据浓密（收入/结算/证明）+ 决策层比价。适配：

1. **直接迁移**：三段式页面骨架、侧栏任务分组+副标注、统计卡排（收入/笔数/履约/新鲜度天然适配）、纸片卡体系、克制动效、四层字阶+大号等宽数字、"浅底同色"提示条。
2. **按场景调整**：①链上数据要加"可核验"视觉语言——每个关键数字旁配哈希缩写/外链小图标（scan），形成"数字+证据"的成对模式（AIsa 没有这个概念，是我们的差异化）；②双模式需要 AIsa 没有的"模式身份"——落地页→连接钱包→Provider/Consumer 选择后，两个工作台用同一骨架但顶部主色微差（如 Provider 深蓝/Consumer 青绿）标识身份；③决策层比价表保留我们的四分量条形（信息图形），配色纳入单色体系。
3. **不适合照搬**：AIsa 的"账户/计费"中心叙事（我们是无托管、钱包即账户——余额概念换为"钱包余额/授权额度"双数）；营销型 GTM/推荐位（赛时无意义）。

## 附：官网与登录页补充（2026-10-07 二次调研）

**官网首页**：深色底营销页——顶部细导航 + 居中大标题/副语 + 主次双 CTA + 下方 logos/功能卡分区；与控制台的浅色纸片风形成"外营销内工具"的明暗反差。可迁移：落地页用深色叙事面制造第一印象，进入控制台后切浅色工具面（明暗切换本身成为"从故事进入工作"的仪式感）。

**登录页（auth.aisa.one）**：居中窄卡（~400px）——logo+产品名、居中标题、**四条登录路径纵排大按钮**：Continue with Google / Continue with GitHub / 邮箱 Continue / **Continue with a wallet**（AIsa 自己就有钱包登录）、分隔线+注册切换、下方中英语言切换与主题切换。按钮为通栏白底描边款+品牌图标，卡片外大面积留白。

**CoinCall 登录形态裁决（发起人 2026-10-07）**：我们的登录页=落地页+钱包登录合体——**连接钱包即登录**（无邮箱/无第三方），登录动作完成后在同一屏出现身份二选一大卡：**"I'm a provider" / "I'm a consumer"**（英文主标签+中文副语），选择后进入对应工作台；/welcome 与 /choose 合并为一个"登录+选身份"的单页流。
